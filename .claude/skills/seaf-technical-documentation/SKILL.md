# Technical Documentation

## Purpose and activation
Update setup, API, architecture or operating documentation to reflect implemented behavior.

## Required inputs
Code livré, commandes vérifiées, public et documentation existante.

## Procedure
Mettre à jour les pages concernées près du code. Expliquer installation, configuration, exécution et contrats selon les besoins. Vérifier liens et exemples; documenter les limites réelles et décisions importantes.

## Engineering constraints
Respecter le périmètre et les permissions de l'utilisateur; préserver le travail existant. Ne jamais inventer une observation ou un résultat. Lire seulement le contexte pertinent; demander une précision uniquement si elle change la correction ou la sécurité de l'action.

## Expected outputs
Documentation concise et exemples copiables.

## Validation checklist
Aucune fonction imaginaire; exemples cohérents avec le code; secrets exclus.
