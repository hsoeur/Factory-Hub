# Software Architecture

## Purpose and activation
Design component boundaries and contracts for changes with meaningful architectural impact.

## Required inputs
Exigences, carte du code, interfaces et contraintes.

## Procedure
Comparer les solutions réellement pertinentes; retenir la plus simple. Définir frontières, flux de données, contrats, erreurs et dépendances. Consigner les décisions significatives avec alternatives et conséquences dans un ADR.

## Engineering constraints
Respecter le périmètre et les permissions de l'utilisateur; préserver le travail existant. Ne jamais inventer une observation ou un résultat. Lire seulement le contexte pertinent; demander une précision uniquement si elle change la correction ou la sécurité de l'action.

## Expected outputs
Schéma ou description des composants, contrats et ADR si justifié.

## Validation checklist
Conventions conservées; cycles évités; complexité justifiée; compatibilité évaluée.
